# 日志设计：给 agent 装一只记录自己行为的黑匣子

这份文档回答一个问题：**怎么证明 agent 做的事是它该做的事？**

答案不是"看它怎么说"，是"看程序记了什么"。所以这条设计的全部重量都压在
一句话上——**日志由程序写，agent 改不了。**

## 一、为什么日志和知识库必须是两个仓库

一句话：**知识要求"对"，日志要求"全"。**

同一个机制管不了两个方向：

| | 知识（Forge-KnowledgeHub） | 日志（Forge-Logs） |
|---|---|---|
| 装什么 | 通过准入的结论 | 全部事件，包括失败的、被拒的、没用的 |
| 准入门槛 | 三道闸 + 有效期 | **没有闸** |
| 错了怎么办 | 一条都不许错 | 记录本身不谈对错，只谈全不全 |
| 谁写 | 程序投影 + 人复核 | **只有程序**，人几乎不写 |
| 失败一次意味着 | 知识被污染 | 丢了一次观察机会 |

用知识库的规矩管日志，会把"试了、没用、推翻了"全部滤掉——而那些恰好是
调试时唯一想看的东西。

用日志的规矩管知识库，三个月后没人能从里面找出任何一条能信的东西。

## 二、三条硬规矩

### 规矩 1：只有程序写

不是"建议程序写"。是**agent 没有那个工具**。

插件注册了 11 个工具，没有一个是写日志的。日志由适配器在每次工具调用
**返回之后**自己调 `kopt log-event` 写，字段是适配器算出来的。

为什么这么较真：你要用日志来判断 agent 是否符合预期。如果日志是 agent
自己写的，它写的正是你要检查的东西。**用被检查者提供的材料去检查被检查者，
那叫自证清白。**

### 规矩 2：只追加

`calls.jsonl` / `actions.jsonl` 用 `ab` 打开，永久追加，不改旧行。
不提供"删除一条"的命令，也不打算提供。

### 规矩 3：写不进去要吵，不许静默跳过

- `logRoot` 没配 → 插件启动时 warn 一声，日志关闭；
- 落盘失败 → `eventlog.py` 抛错（`A log that silently stops is worse than no log`）；
- `log-event` 缺 `--log-root` / `--session` → **exit 2，不猜默认路径**。

**「以为记了其实没记」比「没记」难查十倍。** 所以宁可吵。

## 三、日志里有什么

```
<logRoot>/<yyyy>/<mm>/<dd>/<session_id>/
    manifest.json    这次会话是谁、跑在哪、什么时候开始
    calls.jsonl      每次工具调用：工具名、参数、退出码、耗时
    actions.jsonl    每次受约束的动作：被 guard 挡下的写入、被闸门拒的操作
    notes.md         agent 自己的备注，每条都标 author=agent
```

`calls.jsonl` 一行长这样：

```json
{"at": "2026-10-26T13:53:13.891+00:00", "session": "smoke-test",
 "event": "tool_call", "tool": "kopt_guard",
 "args": {"paths": ["spec.toml"]}, "exit": 6, "ms": 157}
```

**退出码是有意义的那一列。** `exit=6` 不是"调用失败"，是"这次调用被正确地
挡下了"。区分这两件事正是日志的用途之一。

## 四、agent 能写什么：`notes.md`，而且会被标出来

agent 有时确实需要说一句"我为什么这么试"。这份需求是真的，堵死它只会让
agent 把这句解释塞进别的地方。

所以给一个出口，但给它三个限制：

1. **单独的文件夹、单独的文件**，混不进 `calls.jsonl`；
2. **每一条渲染出来都带 `author=agent`**；
3. 文件头写死一句：*让 agent 按预期工作的证据是 calls.jsonl / actions.jsonl，
   不是这份备注。*

三条例外的出口，比一条没有出口的禁令更可靠。因为禁令只会被绕过。

## 五、它对"可追溯"到底保证了什么

必须说清楚，否则就是在吹牛：

**它保证的：**
- 每一次工具调用都有记录，包括失败和被拒的；
- 记录的时间顺序是真实的（`at` 由程序打）；
- 退出码不会被"美化"；
- agent 的备注和程序的事件在物理上分开。

**它不保证的：**
- **不是防篡改的审计链。** agent 理论上能自己拼 `kopt log-event` 写一条假事件。
  这防的是遗忘和偷懒，不是恶意伪造。
- 防伪造要靠 git 提交历史 + 人复核。`Forge-Logs` 是 git 仓库，就是为了这个：
  每条日志都有提交者、有提交时间、有 diff。
- 日志不产生任何结论。**它永远不是证据的来源，只是过程的记录。**

把这两栏分开写，是因为一份"看起来能证明一切"的日志，比一份明确承认边界的
日志危险得多。

## 六、还没做的

- **没装进 DSH 跑过真实会话。** 现在的证据是 `smoke.mjs` 里 9 次工具调用
  全部落盘，是适配器层面的验证。
- **没有自动 push。** 日志写完还在本地 checkout 里，由人或定时任务提交推送。
  自动推需要凭据和冲突策略，那是另一件事。
- **没有过期清理策略。** 日积月累会变大，暂时按 git 仓库的正常方式处理。
